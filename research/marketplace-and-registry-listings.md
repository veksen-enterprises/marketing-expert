# Marketplace, registry and review-site listings: requirements, review, ranking, fees, and what the research shows

Researched 2026-10-05 for the playbook knowledge/marketplace-and-registry-listings.md. Scope: software marketplaces and registries where a product can be listed and found (MCP registries and directories, GitHub Marketplace, VS Code Marketplace and Open VSX, JetBrains Marketplace, Chrome Web Store, Atlassian, Slack, Zapier, Shopify, Salesforce AppExchange, HubSpot, the AWS, Google Cloud and Microsoft marketplaces, npm, PyPI and crates.io), B2B review sites (G2, Capterra, TrustRadius, Gartner Peer Insights), and research on what joining a platform ecosystem does to a firm. Mobile app stores are out of scope: see research/app-store-search.md, research/app-store-featuring-and-launch.md and research/app-discovery-outside-stores.md.

**Builds on, does not repeat.** research/small-bets-presence.md Bet 1 (listings as a small bet: entry gates, a 90-day stop rule, the G2-vs-independent dispute on whether review sites feed AI answers, the MCP crawl preprints) and Bet 7 (integrations; Ceccagnoli et al. 2012 abstract). research/platform-and-feature-risk.md (platform-owner entry research and access-cutting cases). research/developer-tools.md items 17–18 (Vercel Marketplace; GitHub Actions). ## Sources

### A. MCP Registry and other MCP directories

1. **MCP docs, "The MCP Registry".** https://modelcontextprotocol.io/registry/about [first-party] [read 2026-10-05, re-checked]. Still "currently in preview. Breaking changes or data resets may occur before general availability." Metadata only (`server.json`) pointing at npm, PyPI, Docker Hub and so on; open- and closed-source servers accepted if publicly installable or reachable; private servers not accepted. "Intended to be consumed primarily by downstream aggregators"; "not intended to be directly consumed by host applications". Metadata "deliberately unopinionated"; aggregators add curation and ratings. Namespace proof through GitHub, DNS or HTTP challenges. Security scanning is delegated to package registries and aggregators.
2. **modelcontextprotocol/registry README.** https://github.com/modelcontextprotocol/registry [first-party] [read 2026-10-05]. "API freeze (v0.1)" announced 24 October 2025. Publish with the `mcp-publisher` CLI; GitHub OIDC lets CI publish without stored secrets.
3. **MCP Registry moderation policy.** https://modelcontextprotocol.io/registry/moderation-policy [first-party] [read 2026-10-05]. Removes only illegal content, malware, spam and "completely broken servers"; does not remove low-quality, vulnerable or duplicate servers. Removal sets status "deleted"; appeals by GitHub issue. Consumers "should assume minimal-to-no moderation".
4. **MCP Registry aggregators guide.** https://modelcontextprotocol.io/registry/registry-aggregators [first-party] [read 2026-10-05]. Sub-registries implement the OpenAPI spec and may add `_meta` such as ratings, download counts and security-scan results. Poll about once an hour. The API itself offers pagination and an `updated_since` filter only, so no ranking.
5. **GitHub changelog, "GitHub MCP Registry" (16 Sep 2025).** https://github.blog/changelog/2025-09-16-github-mcp-registry-the-fastest-way-to-discover-ai-tools/ [first-party] [read 2026-10-05]. Launched with "a curated selection" of servers.
6. **GitHub blog, how to find and manage servers with the GitHub MCP Registry (24 Oct 2025).** https://github.blog/ai-and-ml/generative-ai/how-to-find-install-and-manage-mcp-servers-with-the-github-mcp-registry/ [first-party] [read 2026-10-05]. 44 vetted servers then; listing required contacting GitHub partnerships; self-publication "expected in the next couple months". Users browse "by tags, popularity, or GitHub stars"; told to check "GitHub stars and org verification".
7. **github.com/mcp.** https://github.com/mcp [first-party] [read 2026-10-05]. Showed 367 servers. Large counts beside entries may be GitHub stars (not confirmed). GitHub says self-published servers in the open registry will appear automatically [snippet-only, GitHub blog]; the filter that keeps the count far below the open registry's is not documented.
8. **Docker MCP Catalog contributing guide.** https://github.com/docker/mcp-registry/blob/main/CONTRIBUTING.md [first-party] [read 2026-10-05]. Submit by pull request; licence must allow use ("MIT or Apache 2 are great, GPL is not"); Docker approves; live "within 24 hours" after approval. Docker-built images get signatures, provenance, SBOMs and automatic security updates.
9. **Claude Connectors Directory, submission.** https://claude.com/docs/connectors/building/submission [first-party] [read 2026-10-05]. "Anyone on a paid Claude plan can submit." Remote HTTPS servers only (local desktop-extension listings "are deprecated"); every tool needs a `title` and a read-only or destructive annotation; OAuth 2.0 for authenticated services; docs, privacy policy, support contact; a populated reviewer test account. Automatic policy scan, then listed by default as "Community"; human review times "vary with queue volume". Listing slug "permanent once published".
10. **Claude Connectors, verification.** https://claude.com/docs/connectors/verification [first-party] [read 2026-10-05]. Anthropic may escalate listings "flagged as highly useful" to a Verified review; "There's no separate application" for the label, which "affects how the connector is displayed and discovered".
11. **Claude Connectors, after publishing.** https://claude.com/docs/connectors/building/after-publishing [first-party] [read 2026-10-05]. Plugin owners get usage data up to 90 days: installs by source and a "Directory funnel" of listing views, install clicks and installs. Connector delisting by email to the review team.
12. **OpenAI Apps SDK, submission.** https://developers.openai.com/apps-sdk/deploy/submission [first-party] [read 2026-10-05]. The dashboard and directory now call submissions "Plugins". Automated validation, then review with test cases, credentials and a video walkthrough. "Only one review can be active per plugin." Server changes are picked up by daily scans; metadata changes need re-review.
13. **OpenAI app submission guidelines.** https://developers.openai.com/apps-sdk/app-submission-guidelines [first-party] [read 2026-10-05]. Submissions "must come from verified individuals or organizations"; privacy policy; tested on desktop and mobile. Selling digital goods (subscriptions, credits) "is not allowed"; physical goods through external checkout are. Tool descriptions may not "manipulate how the model selects or uses other plugins". Strong performers may get "directory placement or proactive suggestions".
14. **Smithery, publish docs.** https://smithery.ai/docs/build/publish [vendor] [read 2026-10-05]. Publish by URL (Streamable HTTP) or bundle; automatic capability scan; an "official-vendor verification checklist". Ranking not documented.
15. **PulseMCP, submit page.** https://www.pulsemcp.com/submit [vendor] [read 2026-10-05]. Submissions paused (page updated 3 Sep 2026); tells developers to publish to the official registry, which it "will automatically ingest" when it resumes.
16. **Glama MCP server directory.** https://glama.ai/mcp/servers [vendor] [read 2026-10-05]. Sorts: relevance, recent usage, date, weekly npm/PyPI downloads, GitHub stars, recent stars. A–F grades for licence, quality, maintenance. About 96,657 servers listed at read time, of which 6,488 marked official and 6,533 claimed.
17. **mcp.so.** https://mcp.so/ [vendor] [read 2026-10-05]. Sorts: featured (hand-picked), popular, latest, stars; "Trending this week"; an "Advertise" link with no public price.
18. **VS Code docs, MCP servers.** https://code.visualstudio.com/docs/copilot/customization/mcp-servers [first-party] [read 2026-10-05]. `@mcp` in the Extensions view shows "available MCP servers in the gallery"; the source registry is not named. That it is fed by GitHub's registry appears only in practitioner posts [snippet-only].

### B. Developer marketplaces: GitHub, VS Code, Open VSX, JetBrains, Chrome

19. **GitHub Docs, publishing actions in GitHub Marketplace.** https://docs.github.com/en/actions/how-tos/create-and-publish-actions/publish-in-github-marketplace [first-party] [read 2026-10-05]. Public repo, one `action.yml` at the root, unique name, developer agreement, two-factor authentication. "Published immediately" with no review. Verified creator badge by request to GitHub partnerships; lost on transfer unless the new owner is verified. Also research/small-bets-presence.md item 2.
20. **GitHub Docs, requirements for listing an app.** https://docs.github.com/en/apps/github-marketplace/creating-apps-for-github-marketplace/requirements-for-listing-an-app [first-party] [read 2026-10-05]. Paid GitHub Apps need "a minimum of 100 installations"; paid OAuth apps 200 users; owner must be a verified publisher organisation; monthly and annual billing. If a paid version is sold outside Marketplace, at least one paid plan must be offered in Marketplace. Integration must go "beyond authentication".
21. **GitHub Docs, pricing plans for Marketplace apps.** https://docs.github.com/en/apps/github-marketplace/selling-your-app-on-github-marketplace/pricing-plans-for-github-marketplace-apps [first-party] [read 2026-10-05]. Up to 10 plans; free, flat-rate or per-unit; free trials fixed at 14 days.
22. **GitHub Docs, receiving payment.** https://docs.github.com/en/apps/github-marketplace/selling-your-app-on-github-marketplace/receiving-payment-for-app-purchases [first-party] [read 2026-10-05]. GitHub keeps 5% (25% before 1 January 2021); payout the month after revenue reaches $500.
23. **GitHub Docs, Marketplace badges.** https://docs.github.com/en/apps/github-marketplace/github-marketplace-overview/about-marketplace-badges [first-party] [read 2026-10-05]. Verified publisher (domain and email verified, 2FA) versus a "requirements met" badge; unverified publishers "cannot change their pricing plan". "GitHub does not analyze or inspect third party code."
24. **GitHub Marketplace listing page.** https://github.com/marketplace?type=actions [first-party] [read 2026-10-05]. Default "Sort: Popularity". App review time is not documented.
25. **VS Code docs, publishing extensions.** https://code.visualstudio.com/api/working-with-extensions/publishing-extension [first-party] [read 2026-10-05]. Verified publisher: an extension listed 6+ months, a domain 6+ months old, DNS TXT record, review within 5 business days. Personal access tokens retire 1 December 2026. "Remove" is irreversible and the name cannot be reused; "Unpublish" keeps stats. No payment system. Also research/small-bets-presence.md item 4.
26. **VS Code docs, extension runtime security.** https://code.visualstudio.com/docs/configure/extensions/extension-runtime-security [first-party] [read 2026-10-05]. Malware scan on every publish and update, rescans, sandbox testing, name-squatting block, secret scanning, a block list that uninstalls flagged extensions; users confirm publisher trust on first install.
27. **VS Code docs, extension manifest.** https://code.visualstudio.com/api/references/extension-manifest [first-party] [read 2026-10-05]. Up to 30 keywords; categories improve filtering; display name and description used for search.
28. **VS Code docs, Extension Marketplace.** https://code.visualstudio.com/docs/configure/extensions/extension-marketplace [first-party] [read 2026-10-05]. In-editor sorts: installs, rating, name, published date, update date; `@popular`, `@recommended`. Workspace recommendations: VS Code "prompts a user to install the recommended extensions" when a workspace is first opened.
29. **Microsoft developer blog, "Security and trust in Visual Studio Marketplace" (11 Jun 2025).** https://developer.microsoft.com/blog/security-and-trust-in-visual-studio-marketplace/ [first-party] [read 2026-10-05]. In 2025 so far, "reviewed 136 extensions for malicious code and removed 110".

39. **JetBrains, plugin search ranking.** https://plugins.jetbrains.com/docs/marketplace/plugins-ranking.html [first-party] [read 2026-10-05, re-checked]. 40. **JetBrains, verified vendor badge.** https://plugins.jetbrains.com/docs/marketplace/verified-vendor-badge.html [first-party] [read 2026-10-05; numeric criteria snippet-only]. 41. **Chrome Web Store, review process.** https://developer.chrome.com/docs/webstore/review-process [first-party] [read 2026-10-05]. 42. **Chrome blog, review updates (20 Aug 2026).** https://developer.chrome.com/blog/cws-review-updates-2026 [first-party] [read 2026-10-05, re-checked]. 43. **Chrome Web Store, discovery.** https://developer.chrome.com/docs/webstore/discovery [first-party] [read 2026-10-05]. 44. **Chrome Web Store, featured products policy.** https://developer.chrome.com/docs/webstore/program-policies/featured-products [first-party] [read 2026-10-05]. Categories never featured include VPNs, video downloaders, crypto and gambling.

### C. SaaS app marketplaces

47. **Atlassian Marketplace app approval guidelines.** https://developer.atlassian.com/platform/marketplace/app-approval-guidelines/ [first-party] [read 2026-10-05]. No install minimum. Name as "App X for Jira", not "Jira App X". Privacy policy and docs required. Review typically "10-15 business days"; higher partner tiers get faster review.
48. **Atlassian, pricing, payment and billing.** https://developer.atlassian.com/platform/marketplace/pricing-payment-and-billing/ [first-party] [read 2026-10-05, re-checked]. Partner share from 1 April 2026: Forge 84%, Connect 80%, Data Center 75%; from 1 October 2026: Forge 83%, Connect 75%, Data Center 75%. From 1 January 2026, "100% of gross revenue earned on Forge, up to $1 million" lifetime, for pure Forge apps (no Connect modules).
49. **Atlassian blog, revenue share changes for 2026 (5 May 2025).** https://www.atlassian.com/blog/development/updates-to-marketplace-revenue-share-2026 [first-party] [read 2026-10-05]. Before 2026 the partner share was 85% for cloud apps.
50. **Atlassian blog, extended timelines (3 Nov 2025).** https://www.atlassian.com/blog/development/extended-timelines-for-marketplace-revenue-share-changes [first-party] [read 2026-10-05]. Moved each step three months later.
51. **Atlassian, Marketplace search results and rankings.** https://developer.atlassian.com/platform/marketplace/marketplace-search-results-and-rankings/ [first-party] [read 2026-10-05]. 56. **Slack Marketplace app guidelines and requirements.** https://docs.slack.dev/slack-marketplace/slack-marketplace-app-guidelines-and-requirements [first-party] [read 2026-10-05]. ## 2. What drives installs

- **No platform publishes where installs come from** (search vs browse vs featuring vs outside links). HubSpot and Claude give per-listing funnels [11][82]; most give none.
- **Most ranking formulas feed on existing use.** JetBrains multiplies by log of downloads and square root of rating [39]; Chrome uses ratings and downloads vs uninstalls [43]; Atlassian adds installs, reviews and support details [51]; Shopify uses merchant behaviour after search and boosts apps gaining traction [69]; AppExchange popularity is installs, clicks and demos [76]; HubSpot's popular and trending rows are install counts [81]; crates.io relevance excludes crates outside the top 1,000 by recent downloads [112]. A new listing therefore starts near the bottom, and the first users have to come from somewhere else. Exceptions that rank on text only: npm and PyPI [103][108].
- **Badges that need usage first**: Built for Shopify (50 paid-shop installs, 5 reviews) [66], HubSpot certification (60 installs, 6 months) [80], VS Code verified publisher (6 months) [25], Zapier tiers (50 / 350 / 3,000 active users) [62], G2 Grid (10 reviews) [119], Capterra Shortlist (20 reviews in 24 months) [122], Gartner Customers' Choice (50 reviews, from companies over $50M revenue) [127].
- **Placement inside the user's work** beats the store page: VS Code prompts installs from workspace recommendations [28]; Zapier gives earlier tiers to partners who embed it [63]. Same logic as pull-request placement in research/early-stage-gtm-devtools.md.
- **Ranks in stores are unstable and concentrated.** 40–60% of a top-50 list changes within a month [142]; top rank carries a demand premium [141]; in Shopify's store, the median app that exited peaked at 8 installs, but later entrants out-grew early movers in 88% of categories [143]. Being early to a category is not what decides it.
- **Package popularity signals are gameable**: downloads include CI and mirrors [105][110]; download pumping and fake stars are documented [107][116][117]. Developers still use downloads, stars and README size to choose [114].
- **Promotion and awards are chosen to serve the platform**, not to reward the best [139]; awards change what winners build and attract rivals [138].

## 3. Cloud marketplaces are a buying channel, not a discovery channel

- Value is procurement: the buyer can spend money already committed to the cloud provider (AWS and Google count marketplace purchases against commitments, Canalys says up to 25%; Microsoft counts 100% for "Azure benefit eligible" offers) [90][92][98][99], and the purchase goes on an existing bill under negotiated terms (private offers) [87].
- Fees are 1.5–3% for SaaS [84][92][95], far below app-store rates; AWS server products are 20% [84].
- Co-sell programs require pipeline and revenue first: AWS ISV Accelerate needs 5 launched and 15 qualified opportunities in 12 months [89]; Microsoft's Azure IP co-sell needs $100K of Azure or marketplace revenue in 12 months [97].
- Market size figures (Canalys $16B in 2023; $163B forecast by 2030) are analyst estimates [99][100]. Vendor survey data say most sellers still do little of their revenue there (35.3% under 1%, 25% at 1–5%) [102] [vendor; sample size not stated].
- No first-party or research source suggests buyers browse these marketplaces to discover new small vendors. The deals are usually sourced by the vendor's own sales team and closed through the marketplace. This is an inference from the program rules, not a measured fact.

## 4. Review sites

- **Collection rules converge**: verify the reviewer's identity and employer; allow incentives only if small (G2 up to $100, Gartner under $25, Capterra "nominal") and not tied to sentiment; ask all customers or a broad cross-section, never only the happy ones [118][123][126]. The FTC rule bans sentiment-conditioned rewards, undisclosed insider reviews and suppression [128]–[130]; whether "consumer" covers B2B buyers is undefined [130], but the platforms' own rules already forbid the same things.
- **Thresholds**: G2 Grid 10 reviews; G2 "Users Love Us" 20 reviews at 4.0+; Capterra Shortlist 20 in 24 months; TrustRadius Top Rated 10 in 12 months (2022); Gartner Customers' Choice 50 in 12 months, excluding reviewers from companies under $50M revenue [119][120][122][125][127]. Reviews decay: G2 weight falls to about 3% after about 3 years [119].
- **Ownership**: G2 now owns Capterra, Software Advice and GetApp [121]. Gartner Peer Insights and TrustRadius are the main independents.
- **Do reviews drive B2B software sales?** No peer-reviewed causal study was found. The one peer-reviewed B2B study (Alibaba sourcing) shows buyers who trade more with a supplier review it less [131], so review counts under-represent loyal customers. The rest is G2-run surveys [132]–[134].
- **Do review sites feed AI answers?** Contested. G2's own surveys and citation analyses say yes (research/small-bets-presence.md items 11–12; item 133 here) [vendor]. An independent June 2026 test of 233 ChatGPT software recommendations found zero direct G2 or Capterra citations, and in G2's own data review count explains under 1% of citation variation (research/small-bets-presence.md item 13) [secondary]. research/ai-assistant-visibility.md item 15 (G2 and Gartner among Perplexity's commercial sources) is still not re-verified, and the stronger general signal there is branded web mentions (item 13, ρ = 0.664) [vendor]. Read: a review profile may be one of many third-party mentions that AI answers draw on; no evidence says it is decisive.

## 5. What joining an ecosystem does to a firm (research)

- **SAP study, now read in full** [135]: small enterprise-software vendors that became SAP-certified partners saw about 26% higher sales on average and a 5.9-point higher chance of an IPO, more for those with strong patents or copyrights or strong sales and service. Observational. The companion paper [136] shows the joiners were already different (only 35 of 1,220 joined; those with stronger IP and downstream capabilities joined more), so the gains partly reflect who chose to join. 1996–2004, one platform, enterprise software. Outcomes at the end of the period: 31% still partners, 46% acquired or merged, 23% no longer listed [135].
- **Certification and awards are levers the platform pulls for its own goals** [137]–[140]: they help those certified (Kiva) but also steer what complementors build and attract competitors to the winner's niche.
- **Platform governance cuts both ways** [144]: long review times weaken the link between user growth and new add-ons.
- **Most listings go nowhere**: 60% of Chrome extensions last one year in the store and 60% are never updated [145]; the median Shopify app that exits peaked at 8 installs [143]; more than half of MCP directory entries are invalid or low-value (research/small-bets-presence.md item 14).
- **Gap**: no peer-reviewed study of Salesforce AppExchange, Atlassian, Slack, HubSpot, Built for Shopify or MCP-registry listings and the vendor's revenue.

## 6. Which listings fit which business type and stage (synthesis)

Fit follows from three facts above: whether the platform ranks on text or on usage, whether there is an entry gate, and whether the buyer already lives there.

- **Developer tool, 0 customers**: package registry entry with a clear name and description (text-ranked on npm and PyPI) [103][108]; GitHub Action if it runs in CI [19]; official MCP Registry if agents are users, because aggregators copy it (PulseMCP explicitly) [1][15]; the editor marketplace where users are (VS Code plus Open VSX, since several AI editors use Open VSX) [25][34]. Free, no review. Expect few installs from the listing itself.
- **Developer tool, first users**: client directories with review (Claude, Docker, OpenAI) once the server is remote and annotated [8][9][13]; JetBrains if the users are there [35]; workspace-recommendation snippet in users' repos [28].
- **SaaS that extends one platform (Shopify, Atlassian, HubSpot, Salesforce, Slack)**: the platform's store is the primary channel, but entry gates and ranking need installs first: HubSpot 3 installs, Slack 10 active workspaces through review, Salesforce security review fee [59][72][79]. Build the first installs by direct sales or the platform's community, then list.
- **Horizontal B2B SaaS**: Zapier integration once the API is stable (tiers unlock placement at 50 active users) [62][63]; review sites once there are 10–20 customers willing to review [119][122]; cloud marketplaces only when deals are large and buyers have cloud commitments [84][98].
- **Sales-led enterprise software, first large deals**: a cloud marketplace private offer when a buyer asks to buy through it or wants to use committed spend; co-sell programs only after the revenue and pipeline gates [89][97].
- **Browser extension**: Chrome Web Store is the only route; slots are limited by quality and usage from August 2026 [42]; ratings now weight recent reviews.
- **Not a fit**: services firms, local businesses and ecommerce brands (see local-seo and marketplaces playbooks). Mobile apps: research/app-store-search.md.

## 7. Listings as platform risk (synthesis with research/platform-and-feature-risk.md)

Dated changes in the last three years, all by first-party notice:
- **Fees rise or fall by decision of the platform.** Atlassian partner share for Connect apps went from 85% to 75% in 2026, Forge to 83% [48][49]; GitHub cut its fee from 25% to 5% in 2021 [22]; Shopify changed its exemption from yearly to lifetime in 2025 [65]; AWS cut fees in January 2024 [84].
- **Entry gates move.** Slack's threshold went from 10 to 5 active workspaces (2025) and back to 10 (2026), and must now hold during a review that can last 10 weeks [57]–[59]. Chrome limits new publishers to two extension slots by default from August 2026 [42].
- **Whole product lines end.** Atlassian Server apps lost support on 15 February 2024; Data Center apps become read-only in March 2029 [54][55]. Chrome removed all Manifest V2 extensions in August 2026 [45]. Cloud Fortified ends in 2026 [53]. AppExchange became AgentExchange [78]. Microsoft merged two marketplaces in 2025 [94].
- **Badges and featuring are withdrawn.** Chrome's Featured badge sunsets in 2026 [42]; badges serve the platform's goals [139].
- **Removal can be fast and one-sided.** JetBrains "at its sole discretion" [35]; Slack delists abandoned apps without notice [56]; VS Code removals are irreversible [25].
- **The platform enters.** Shopify's own chat app reversed two years of de-concentration in that category [143]; research on Amazon, Google and Apple entry is in research/platform-and-feature-risk.md §1, and specialists tend to "double down" while generalists move away [146].
- **Directory infrastructure is young.** The official MCP Registry is still preview with possible data resets [1]; PulseMCP paused submissions [15]; the Claude directory deprecated local listings [9].
- **Mitigations** (from research/platform-and-feature-risk.md §6): own the customer relationship (email and account outside the platform), track the share of new customers per marketplace, read the developer terms for removal and fee-change notice periods (JetBrains: one month; AWS price changes need 90 days' notice) [38][86].

## What this means

1. A listing is necessary where buyers search inside a platform, but it rarely brings the first users: most marketplace ranking feeds on installs, ratings and usage the listing does not yet have.
2. Text-ranked registries (npm, PyPI, the MCP Registry as a feed) reward a clear name and description; usage-ranked stores (JetBrains, Chrome, Atlassian, Shopify, AppExchange, HubSpot, crates.io) reward the first installs you bring yourself.
3. Gated stores (Slack 10 workspaces, HubSpot 3 installs, GitHub paid 100 installs, Salesforce security review) belong after first customers, not before.
4. Cloud marketplaces help close and expand large deals through committed spend; they are not where a small vendor is discovered.
5. Review sites need 10–50 honest reviews before badges appear; collect them from all customers, never filter by sentiment.
6. The best research (SAP) links certified partnership to higher sales, but mostly for firms that were already strong; selection explains part of the gain.
7. Every listing is rented: fees, gates, badges and whole product lines changed in 2024–2026.

## Folklore and weak claims

- **"Listing in many directories brings users."** No study links a registry or directory listing to signups for a small vendor; more than half of MCP directory entries are low-value (research/small-bets-presence.md item 14).
- **"npm ranks by quality, popularity and maintenance."** Removed in December 2024 [104].
- **"Being first in a marketplace category wins it."** In Shopify's store, later entrants out-grew early movers in 88% of categories [143] (preprint).
- **"Marketplace badges guarantee quality."** JetBrains says its verified badge "does not guarantee the quality of plugins" [40]; GitHub "does not analyze or inspect third party code" [23].
- **"Reviews must be on G2 to appear in AI answers."** Contested; see §4.
- **"90% of buyers read reviews before buying."** A 2017 G2-sponsored survey of 548 people [132].
- **"Cloud marketplaces will be $85B / $163B."** Analyst forecasts [99][100]; Tackle survey figures have no stated sample size [101][102].
- **"Joining a platform ecosystem raises sales by a quarter."** Observational, one platform, 1996–2004, joiners self-selected [135][136].
