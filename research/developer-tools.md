## 1. Open source licensing and forks

- **GitHub stars are gameable** [1]. StarScout scanned GitHub events 2019–2024. Raw detection: ~4.53M suspicious stars from ~1.32M accounts on 22,915 repos; after filtering for reliability: ~3.1M fake stars from ~278k accounts on 15,835 repos. Many starred repos were short-lived scam or malware repos (game cheats, crypto bots). The headline "4.5 million" is the raw (suspected) number; the filtered figure is ~3.1M. [research, preprint]
- **HashiCorp / Terraform** [2][3]. 10 Aug 2023: HashiCorp moved core products including Terraform from MPL 2.0 to the Business Source License (BSL, source-available; bars competing commercial use). OpenTF (backed by Gruntwork, Spacelift, Harness, env0, Scalr and others) forked Terraform 1.5.6 as OpenTofu; it joined the Linux Foundation in Sept 2023 and was accepted into CNCF Sandbox on 23 Apr 2025. IBM closed its acquisition of HashiCorp on 27 Feb 2025 (TechCrunch headline: $6.4B; other reports cite ~$7.2B equity value at $35/share). No source links the license change to the acquisition.
- **Redis / Valkey** [4][5]. March 2024: Redis Ltd. moved from BSD-3-Clause to dual RSALv2/SSPLv1 (neither OSI-approved). Within days, contributors and cloud providers forked Redis 7.2.4 as Valkey under the Linux Foundation, BSD-licensed, backed by AWS, Google Cloud, Oracle, Ericsson and Snap. May 2025: Redis 8 added AGPLv3 as a third option; Redis said the forks had created a "level playing field" and it had seen "record growth" since the change [first-party claim]. AWS prices ElastiCache for Valkey about 20% below Redis OSS on nodes and 33% below on serverless [first-party via secondary, not re-verified] — a concrete example of a cloud provider using the fork to compete on price.
- **Elastic / OpenSearch** [6]. Jan 2021: Elasticsearch and Kibana moved from Apache 2.0 to SSPL/Elastic License v2 (from 7.11), citing AWS's hosted service. AWS forked 7.10.2 as OpenSearch (Apache 2.0, April 2021); OpenSearch moved to the Linux Foundation's OpenSearch Software Foundation in Sept 2024. 29 Aug 2024: Elastic added AGPLv3 as an option.
- **Research on relicensing** [7]. arXiv:2411.04739 compared the three cases: in Elasticsearch and Terraform almost all contributions to the original came from vendor employees; forks attracted new contributors; Valkey had a diverse multi-company contributor base (Amazon largest). Forks from relicensing tended to be more organisationally diverse than the originals. Foster et al. (ISJ 2025) study collective-action threats and governance around relicensing and hard forks. [research; snippet-only]
- **GitLab open core** [8]. GitLab describes "buyer-based open core": a large free tier plus paid Premium and Ultimate, priced per user; tiers are assigned by *who buys the feature* — individual contributor (free), manager/director (Premium), executive (Ultimate). Model rolled out in 2018. [first-party]

## 2. Channels and distribution

- **Show HN rules** [9]: for "something you've made that other people can play with"; blog posts, sign-up pages, newsletters and landing pages are off topic; the maker must be around to discuss; make it easy to try "ideally without barriers such as signups or emails"; don't ask friends to upvote or comment. [first-party]
- **GitHub Marketplace for Actions** [18]: actions publish immediately without GitHub review if the repo is public, has a single action.yml at the root, and the name is unique. GitHub announced its 10,000th action (date not captured). [first-party]
- **Vercel Marketplace** [17]: launched with storage providers (Supabase, Redis, Upstash) with integrated billing; later available inside v0 (Vercel's AI app builder) starting with Upstash, Neon and Supabase, so the AI tool can provision those services during generation. [first-party] Illustrates integration marketplaces turning into AI-agent distribution.
- **Docs as learning resource** [15]: in Stack Overflow's 2025 survey, people learning to code in the past year used technical documentation more than any other resource (68%); AI tools 44%. [first-party survey; self-selected sample]
- **Time to first API call** [20]: widely used practitioner term; teardowns credit Stripe's in-docs request runner and one-page quickstart. Not a Stripe-published metric. [vendor/practitioner]

## 3. AI agents as users

- **MCP Registry** [10][11]: launched in preview 8 Sept 2025 at registry.modelcontextprotocol.io as an open catalog and API for public MCP servers; the registry and its OpenAPI spec are open source so others can run compatible sub-registries. [first-party] Secondary sources: API freeze from 24 Oct 2025; still in preview as of mid-2026; namespace ownership verified via GitHub OAuth, GitHub OIDC, or DNS/HTTP domain checks (e.g., publishing com.example/* requires proving example.com). [not re-verified]
- **Tool descriptions are prompts** [14]: Anthropic recommends choosing a small set of well-scoped tools, namespacing related tools with prefixes, returning meaningful (not raw ID) context, making responses token-efficient (e.g., an option for concise output), and prompt-engineering tool names, descriptions and parameter docs; it fixed a web-search tool by rewriting its description. Prefix vs suffix naming had "non-trivial" effects that varied by model — test with evaluations. [first-party]
- **Annotations and trust** [12][13]: MCP tool annotations (read-only, destructive, idempotent, open-world hints) are optional; the spec says clients MUST treat annotations as untrusted unless from trusted servers. Tool descriptions can carry injected instructions ("tool poisoning"), a known attack class. [first-party / industry]
- **Agent adoption** [15][16]: Stack Overflow 2025: 31% of respondents use AI agents (23% at least weekly); 38% did not plan to. [first-party survey] JetBrains (Aug 2026) reported ~39% of professional developers used Claude Code at work in May–Jul 2026, up from 18% in Jan 2026. [vendor; not re-verified]
- **llms.txt**: see research/landscape-2026.md §4 (no evidence of use; Ahrefs 97% of files never requested).

## 4. Enterprise upgrade path

- **SSO tax** [19]: sso.tax lists vendors that put single sign-on only on top tiers, often at 2–4× base price (its own examples go higher). Security teams and some vendors (1Password) argue SSO is a baseline security need. Pricing SSO as a pure upsell creates visible backlash; many devtools still put SSO/SAML, audit logs and SCIM in an enterprise plan. [community/vendor]
