## Errors

### A. The tool gave wrong or misleading data (highest priority)

1. **The word counter glues text across elements, and the lead text becomes misleading** (`src/lib/pageAudit.ts` `text()` / `auditHtml`; `src/lib/crawl.ts:244`). Both use node-html-parser's `.text`, which joins sibling elements with no whitespace. Server HTML for `/ias-calculator` reads `"[Companion]SearchIAS calculatorImbue calculatorReport a Bug"`, which counts as **5** words when the visible text is about **10**. Rendered counts are low by the same mechanism. `leadText` for the imbue page contains `"affix level 990.49% (1 in 204)"`, which an assistant could easily read as "affix level 990.49%" (it is "affix level 99" followed by "0.49%"). This produced the "5-word shell" claim in the answer, and the same count drives crawl_site's `thin` issue.
2. **crawl_site reports a 503 sitemap as "No XML sitemap found"** (`src/lib/crawl.ts` ~line 140: `if (!r.ok) continue;`). `/sitemap.xml` returns 503 locally, but the tool says it was "checked … and /sitemap.xml" and found none. Missing, erroring, empty and invalid are different findings with different fixes. On production, an API outage would make the sitemap return 503 permanently, and the tool would hide that. The run found the 503 only by curling.
3. **Redirect status is hidden.** `audit_page '{"url":"/"}'` returns `status: 200, finalUrl: /search` with no redirect hop or code. crawl_site says "Start URL redirects to http://127.0.0.1:4173/search; crawling that host". That is the same host, so "crawling that host" is wrong, and it gives no status code and no 307-vs-301 warning. The 307 finding in the answer came from curl only.
4. **crawl_site reports "missing h1" ×3 and "thin (5 words)" ×3 without saying the pages are client-rendered shells.** All three pages have an h1 after JS ("Assassin IAS calculator", "Imbue Calculator", "Search GameX items for trade"). The tool description says "Server HTML only", but the issue messages don't. A less careful assistant would tell the founder to "add h1 tags" that already exist. The tool should detect a shell (identical body text across pages, tiny word count, many module scripts) and report one "site renders client-side" issue in place of N misleading per-page issues.
5. **audit_page render mode reports `<head>` facts from the rendered DOM only.** Title, description, canonical, meta robots and OG are taken from `page.content()`, and only word count and h1 are compared with the server HTML. A canonical or `noindex` injected by JS would be reported as present even though non-JS crawlers never see it. This matters here: the server stops running `head` below an `ssr: false` layout (`/planner` server HTML has `<title>GameX Companion</title>`; the route's own title is "Planner"), so the noindex the answer recommends for `/create`, `/planner` and `/stash` would exist only client-side. The tool could not have caught that.
6. **Landing-page heuristics misfire on tools.** "Form with 21 fields. Each field costs conversions; ask only what you need" is about a calculator's inputs. ctaCandidates is junk ("Whirlwind + TrapWhirlwind + Trap", "35 IAS", "0"). "Incomplete Open Graph tags (og:title / og:image)" fires when og:title is present and only og:image is missing. This is noise the assistant has to filter, and a weaker run would relay it.
7. **check_ai_crawler_access checks robots.txt only, yet its findings sound like a verdict on AI access.** It answers "All listed AI bots are allowed on the checked paths" for a site whose content GPTBot, ClaudeBot and PerplexityBot cannot see (client-rendered). It never fetches the checked paths, so it reports no status, no X-Robots-Tag or meta noindex, and no server-HTML word count. It also returns `sitemaps: []` with no finding, despite its description ("Also checks for llms.txt and sitemaps"). Missing `Sitemap:` line → silent.
8. Minor: in render mode, `url` is overwritten by the JS-rewritten URL (`/ias-calculator?mode=ww%2Btrap&…`), so the field no longer shows which URL was audited.

### B. Assistant errors

1. **Repeated the tool's wrong count** ("a 5-word shell (just the nav)") even though it had curled the same pages. See item 5.
2. **The noindex fix as written would not work for half the listed routes.** "Add it to `/admin*`, `/watches`, `/create`, `/planner`, `/stash`…". `__root.tsx` says: "The server stops running `head` at the first `ssr: false` route, so pages under the admin layouts get that layout's title". So `/create`, `/planner` and `/stash` (under the `_admin-only` layout, which has `ssr: false`) would not get a server-side noindex from their own `head`. The robust fix is an `X-Robots-Tag: noindex` header in `server.mjs` for those path prefixes, or a `head` on the layout. The run read `__root.tsx` and quoted it, so this is a missed read, not missing data.
3. **The proposed title is too long:** "Assassin IAS calculator – Whirlwind & trap breakpoints (GameX) · GameX Companion" is about 76 characters. The server's own audit_page flags titles over 60 as likely truncated.
4. **"Every page route is `ssr: false`"** is an overstatement. Items are `data-only`, which the answer itself says later.
5. **No check of whether it can win the calculator queries** (see item 3), and no plan to turn calculator visitors into item-search or watch users. Search traffic that never reaches the database does little for this product.
6. **Missed the `VITE_CALC_ONLY` build mode.** It should be on the "check on production" list, because it changes the `/` redirect target and the nav.
7. Overstated the Bing citation-report claim relative to the playbook (item 8).
8. No tool misuse. The tool log matches the answer, rendering was used where needed, and the local-build limits were stated clearly.

2. **Item-page indexing as a deliberate decision tied to VISION Open Question 1:** "until item lifecycle exists, add noindex… drop items from sitemap.xml… Keep 503 for API failure… return a real 404 (or 410)", with a data-based override ("If item URLs already get meaningful clicks, keep them indexed"). This is the right call for thousands of short-lived trade posts.
3. **Honest AI-search framing:** which bots render JS (vendor-labelled), llms.txt skipped with data, off-site mentions through the existing Reddit and Discord communities in line with "augment, don't disrupt", and a prompt-panel measurement ("named in 4 of 20 runs") instead of a fake rank.

Add a regression test with `<nav><a>Search</a><a>IAS calculator</a></nav><p>affix level 99</p><p>0.49%</p>` → 6 words, with the lead text keeping "99 0.49%" separate. *Why:* every word count, thin flag, client-only share and leadText depends on it, and a glued number ("990.49%") is a factual trap.
2. **Report sitemap and redirect states precisely** (`src/lib/crawl.ts`, `src/lib/pageAudit.ts`). Record each sitemap candidate's status: "sitemap.xml returned HTTP 503 (server error); crawlers retry, but a persistent 5xx hides every URL in it", plus separate notes for 404, empty and unparseable. 3. **Make crawl_site detect a client-rendered site** (`src/lib/crawl.ts`). If most pages have under ~30 words, identical body text and module-script bundles, emit one top-level issue: "Pages appear to be client-rendered shells; h1 and thin results below reflect server HTML only. Run audit_page render=true on each template". Prefix `missing-h1` and `thin` with "(server HTML)". Optionally add `render: true` for the first N pages.
4. **Diff `<head>` between server and rendered HTML in `renderAndAudit`** (`src/lib/pageAudit.ts`). Return `serverHead: {title, description, canonical, robots, og}` next to the rendered values, and flag any canonical, robots or title that exists or differs only after JS ("noindex/canonical added by JavaScript: Google may honour it after rendering; non-JS crawlers won't see it; put it in server HTML or an X-Robots-Tag header"). 5. **Give check_ai_crawler_access a real fetch check** (`src/lib/aiCrawlers.ts`, `src/server.ts` description). 6. **Gate the landing-page heuristics by page type** (`src/lib/pageAudit.ts`). Skip the "form fields cost conversions" flag when the form has no submit or action (an interactive tool), drop button texts that repeat themselves or are numeric from ctaCandidates, and split the OG flag into "missing og:image" and "missing og:title".
