## Errors

1. **The open-source analyzer is left out (omission; the playbook covers it).** The homepage advertises "The analyzer is open source" with a link to github.com/DBTool/analyzer, and VISION calls the adapter layer open source with "Ecto comes next". The `developer-tools` playbook the assistant loaded (tool log step 7) has an "Open source as distribution" section and a first-users line "ship a free tier or open-source core". The answer contains no mention of open source, the repo, adapter contributions or Ecto. Unlike round 1, this is now the assistant's fault, not the server's.
2. **The data-handling disclosure is no longer raised (omission, regression).** The homepage says "Read-only role, and we never write to your DB" (index.astro:258–260) and "It never writes back" (index.astro:461–465), but never says that statistics with real column values are uploaded. The docs say this plainly: "the table statistics contain real values out of your columns" (introduction.md:59), and so does the pricing FAQ ("Some of those statistics include sample values from your columns"). The pricing tooltip says "Parameter values aren't included" (pricing.astro:263), which is true of bind parameters but reads as a broader reassurance. Round 1 raised the homepage gap. Round 2 drops it, even though rule 0 says "Contradictions between the marketing site, the docs and the product are findings in their own right", and the playbook's "Developer trust" section asks for published data flows.
3. **It assumes a GitHub Action exists (unverified claim).** "Publish the GitHub Action on GitHub Marketplace." The repo has no `action.yml`. ci-integration.md wires CI with `uses: docker://ghcr.io/dbtool/collector:latest` (line 134), and the playbook says Marketplace listing needs "an action.yml at the root" of a public repo. A wrapper Action would have to be built first. An Action may exist in another repository, but the answer did not check and presents publishing as a listing task.
4. **The vision fallback is not flagged (same as round 1).** "Then position around that instead" (the production dashboard) conflicts with VISION's "It is not a gate" and "push as much as we can toward the keyboard", and the answer does not say so.
5. **VISION is misquoted.** "say 'cost', not 'time', as VISION.md requires": VISION requires saying which measure is meant, not avoiding time.
6. **Mixed bases in the Lifetime comparison (minor numbers error).** "$100 Lifetime deal is below the modelled Pro lifetime value ($256)": $100 is revenue, while $256 is simple gross-profit LTV. The like-for-like figures are about $80 gross profit vs the $244 bounded LTV the answer uses elsewhere. The conclusion ("keep it capped") still holds, and the pricing FAQ already says "Limited spots", which the answer doesn't acknowledge.
7. **An unsourced market claim.** "little search demand for the category yet" is stated as fact with no keyword data, and no tool was used for it.
8. **Claims about ADRs it didn't open.** "ADRs 0031/0032 describe them as part of the engine": the tool log says the ADRs were "consulted by name". The claim is correct (I checked ADR 0031), but the process doesn't support it.
9. **Over the length limit.** 1,318 words against "under about 1,200".
10. **Unexplained jargon** (see item 10): Show HN/HN, LTV:CAC, ICP, venture-style, Dunford.
