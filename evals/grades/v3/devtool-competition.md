## Errors

1. **Retired package presented as shipped (misattribution).** "MCP server, both hosted at `/mcp` … and a local package with `explain_query`, `optimize_query`, `simulate_with_index` (`packages/mcp-server/src/server.ts` line 68)". That package is the retired stdio server. apps/api/src/mcp/skill-tool-names.spec.ts:9 says "it described the retired stdio server, so every tool it named was missing from the hosted one", and packages/mcp-server/package.json has `"private": true`. The hosted `/mcp` registers `optimize_query` but neither `explain_query` nor `simulate_with_index` (mcp-tools.ts:667–897). The tool log even records that the pricing page's `suggest_indexes` and `predict_at_scale` don't exist, but the answer drops that finding and lists the retired names as product features.
2. **Two wrong line references in pricing.astro.** "Pricing marks MCP and rewrites '(soon)' (`pricing.astro` lines 74–75, 279–290)." The "(soon)" labels are at lines 71–72, 120 and 130, and the "Soon" table cells at 240 and 250. Line 74 is "Everything in Free", and lines 279–290 are the Discord and "Open source analyzer" rows. "Pricing claims an OSI-approved open-source analyzer (line 302)." The OSI tooltip is at line 291, and line 302 is `</section>`. The substance is right, but a founder who follows the references will land on the wrong lines.
3. **Self-hosting listed as shipped.** It appears under "Shipped per docs and code: … self-hosting (`guides/self-hosting.md`)" and is then offered as a current protection: "self-hosting with the planner". The guide and docker-compose.self-host.yml exist, but the ADR table marks 0020, 0021, 0023 and 0028 "Accepted, not built (self-hostable epic)", and 0022 (the fork) "built in postgres-newer, unpublished". analyzer.mdx says "No setting keeps the data on your machine." Round 2 had this row right ("Guide exists; parts not built").
4. **CI gate listed as plainly shipped (the round-2 error, still present).** "CI gate with PR comment (docs `guides/ci-integration.md`)". The ADR table has 0003 (the PR comment as a handoff to triage) "Accepted, not fully built", 0037 (what CI warns on and what it blocks on) "Accepted, being built", and 0013 (schema-change approval) "not fully built". The gate runs, but its rules are being changed.
5. **Competitor fact wrong and unhedged.** "self-hosting with the planner, which SaaS monitors don't offer." pganalyze sells a self-hosted Enterprise Server, to my knowledge. This line sits in the "What protects you now" paragraph, not in the section labelled unverified.
6. **Overclaim about agents.** "the coding agents don't have the planner, the statistics or the history." An agent can run `EXPLAIN` against a dev Postgres. VISION line 113 says "Anyone can run `EXPLAIN`." From PG18, `pg_restore_relation_stats` / `pg_restore_attribute_stats` let stock Postgres take injected statistics. What the agent lacks is production-matched statistics, history and triage, not the planner. The PG18 risk (round-2 Error 8) is still not mentioned.
7. **"Neutral across agents" stated as a protection, without its limits.** "You are neutral across agents (Claude Code, Cursor, Zed)". "Zed" comes from marketing copy (pricing.astro:122). The docs show setup only for Claude Code (`claude mcp add`, `.claude/settings.json` hooks: "Examples are for **Claude Code**"). CI generation is GitHub Actions only, and `setup_ci` says "Detection is Node-only today". Round 2 found these dependencies, and this answer drops them.
8. **The agent-integration gap was dropped.** The answer cites using-with-llms.md as proof that guardrail hooks shipped, but lines 65–66 of that page tell the agent to call `analyze_query` / `recommend_indexes`, which the hosted `/mcp` does not register. That bears directly on the answer's own point that "agents often don't" call the tool. It is a cheaper fix than any of the three moves, and it is missing.
9. **Copy cost still not quantified.** "Datadog DBM: sold per monitored host … A free check at development time doesn't grow its host count". "pganalyze … nothing it earns would suffer". The reasoning is qualitative, with no list prices and no "unquantified" label. Playbook decision rule 1 asks for "which revenue or margin it would destroy".

Without measured runtimes on a scaled dataset, a sceptic can call the benchmark circular. This is round-2 Error 9, unchanged.
11. **Risk questions partly answered.** Playbook question 1 ("what share of our users would still pay") and question 5 ("Do we own customer identity, billing and contact?") are not addressed. The Anthropic access-cut precedents in the playbook (Windsurf, Jun 2025; consumer-credential block, Jan 2026) bear on a channel built through Claude Code. The answer reduces them to "MCP client terms" on a watch list.

The same flaw recurs in Move 3, so the fix either wasn't made or isn't enforced. Put it in the `competitive_strategy` prompt's output template as well as in INSTRUCTIONS, with an example: metric "MCP/CI connect rate in 7 days"; stop "below 15% after 4 weeks → test onboarding, not the homepage".
4. **One action per move (server).** Nothing says a move must be a single action. Add to INSTRUCTIONS rule 6: "Each move is one action one person can start this week. Split anything with its own timeline into its own move or into 'do now regardless'."
5. **Protections stated without their erosion risks (prompt).** Round 2's proposed prompts.ts step-5 fix ("for each thing you call a protection, name what could erode it and when") would have caught Errors 5, 6 and 7. Add: "Check each protection against the named competitors' current offerings, and label it unverified when it rests on your own knowledge."
6. **Self-graded benchmark (developer-tools playbook).** Still not addressed. Add: "Judge with a measure the reader trusts (measured runtime on a scaled dataset), not only your own tool's output."
7. **Length and jargon (server partly).** The answer is down to 1,519 words, still over. Have `competitive_strategy` cap the competitor list at one line per alternative, and add "counter-positioning" and "win/loss" to the define-or-drop list.
